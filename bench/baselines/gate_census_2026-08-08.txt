WHAT THIS SHOWS (2026-08-08) -- deterministic, one run, no noise floor
===========================================================================
Corpus: FourPeople(720p low-motion, the campaign's worst BD regression),
shields(720p detail), in_to_tree(720p foliage), mobile/foreman/bus (CIF).
Config: gatecheck defaults -- Preset::Quality, LIBRARY defaults otherwise
(cabac on, bframes 0). READ THE CONFIG CAVEAT AT THE BOTTOM.

1. FOUR OF FIVE VETO GATES NEVER FIRE. aq_grain_veto, sub8_grain,
   mbtree_grain and mbtree_backoff read 0.0% on EVERY clip, with denominators
   up to 95,809 consultations. They have zero discriminating power on this
   corpus. A gate that never abstains is not routing anything.

2. intra_rd NEVER EXECUTES. `intra_rd_flip` is 0/0 on all six clips: the gate
   requires `sig.grain_signature()` and none of these clips are grainy. Yet
   `tune_intra_rd: true` shipped default-on as a campaign win. Its BD
   contribution on this corpus is necessarily EXACTLY ZERO.

3. shape_rd's TEXTURE VETO ACTUALLY WORKS -- and it is the gate the code
   disowns. `shape_rd_flip` is 0/0 on mobile_cif (the high-texture clip; the
   median_var>1000 veto holds it) and 35-42% elsewhere. That is real
   discriminating power, from the guard whose own comment says "Delete this
   guard the moment a real mechanism is found."

4. THE SATD PROXY IS WRONG TWO-THIRDS OF THE TIME. `sub8_rd_revert` runs
   58.7-74.2%: the RD pass overturns the cheap SATD split pick on most
   macroblocks. That justifies paying for RD, and simultaneously says the
   proxy driving the fast path is badly calibrated.

5. sub8_split is genuinely content-adaptive: 19.5% (in_to_tree) to 59.8%
   (mobile) -- a 3x range across content. This one routes.

===========================================================================
CONFIG CAVEAT -- and a hypothesis this census RAISED and then REFUTED
===========================================================================
`mbtree_spread` latches mb-tree OFF on 5 of 6 clips but NOT on FourPeople,
which is the clip that regressed worst (+8.45% fast / +5.67% quality). That
looked like a direct causal lead. It is WRONG, and the refutation was one run:
encoding FourPeople with mbtree ON vs OFF is BYTE-IDENTICAL (+0.00% BD).

Why: `lookahead_active()` is `mbtree && bframes == 0 && bitrate == 0`, so
mb-tree CANNOT RUN with B-frames enabled. This census was taken at bframes=0
(library default); the BD measurement used `--bframes 2`. THE CENSUS AND THE
QUALITY MEASUREMENT DESCRIBED DIFFERENT PROGRAMS.

The rule this earns: an abstention census is only meaningful in the SAME
configuration the quality number was taken in. Take both under one config, or
the fire rates describe code the quality run never executed.

Second-order finding worth its own ticket: mb-tree defaults ON but is mutually
exclusive with B-frames, which are also default-on in every x264-comparable
arm. In the configuration we benchmark against x264, mb-tree is dead code.
